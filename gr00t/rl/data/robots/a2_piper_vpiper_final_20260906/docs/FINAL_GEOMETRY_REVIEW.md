# 最终安装几何复核

## 1. 输入与依据

本次机械尺寸只依据本对话实际可读文件：上传的 `A2足端版简化模型Vpiper.step`、`a2_piper.urdf`、Worker自包含包中的27个机器人mesh、上一轮派生安装件包，以及Owner实拍与“厚5 mm、宽度取Vpiper头部窄边”的更正。没有读取远程新分支来静默替换资产，也未查看训练日志或checkpoint。

`source/source_provenance.json` 保存各输入的大小和SHA-256，以及逐个与Worker包核对的原始资产哈希。源URDF与上传文件逐字节相同。原照片没有做尺度反推；它用于确认部件叠放关系，不能确定trunk物理原点或PiPER长槽锁紧后的外参。

在线文档仅核对URDF/MJCF格式语义，未用外部机器人尺寸补全事实；参见 `FORMAT_REFERENCES.md`。

## 2. 金属板宽度为什么选100 mm

Vpiper上承托面不是等宽矩形。其局部坐标原点取四个70×70 mm安装孔的XY中心、下支脚平面Z，+X朝A2头部，+Y朝左，+Z朝上。

从精确STEP上承托面外轮廓读出：

| 轮廓段 | 局部几何，mm |
|---|---|
| 后方宽端 | X=−125；Y约为−86.552144到+86.552146 |
| 后段肩部 | X=−125到−25，宽约173.104290 |
| 肩部过渡 | X=−25到−5，逐渐收窄 |
| 前方窄段侧缘 | X=−5到+115，Y=−50和+50 |
| 前端两个圆角 | R=10 |
| 最前端直线 | X=+125，Y=−40到+40，长80 |

因此，“窄头整体宽”是 **100 mm**，“最前端直线边长”是 **80 mm**。本版按通常安装件外宽的含义采用前者；不是把Owner的文字擅自记录成一次100 mm实测。该解释、CAD边坐标与两种宽度均留在JSON和图中。80 mm还会把原CAD中Y=±40 mm的部分安装孔中心放到矩形板边缘，不能在没有新孔系的情况下直接把它当作完整板宽。

最终板为局部 `X=[−125,+125] mm、Y=[−50,+50] mm、Z=[0,5] mm` 的矩形。相对旧板，左右各收回约36.552145 mm。长度250 mm沿用，未改变Vpiper本体形状，未改变板的XY中心或厚度。板真实长槽、通孔、圆角/倒角、表面处理仍未测；rectangle不是精确加工实体。

板的下表面放在Vpiper上承托面，本地Z沿+Z增加5 mm。新STL以米为单位，STEP以毫米为单位；URDF与MJCF不会再做1000倍隐式缩放。板的visual和collision分别是同尺寸网格和box，不存在只改外观没改碰撞的问题。

## 3. 重新从原STEP建立trunk配准

重新解析约93 MiB原STEP的实体依赖，提取主件part4、支撑件part5，以及trunk实体#717的3873个精确拓扑顶点。另保留#717单实体STEP子集供本地复查，不要求重新下载整个装配。子集只缩减包含哪些实体的representation，未修改几何面、边、顶点或单位。

把CAD顶点与原trunk.STL顶点统一为mm，使用：

```text
p_trunk = R * p_STEP + t
R = diag(-1,+1,-1)  # 绕Y轴180度的正旋转，不是镜像
 t ≈ [-0.006392963, -0.052512042, +0.106392439] mm
```

先做稳健平移配准，再做独立六自由度拟合交叉验证；额外旋转仅约10^-7度量级。没有用PiPER安装高度或金属板去拟合这个变换，故不是先选择147.432 mm再把CAD强行对上。

顶点最近邻残差的P50约0.000016 mm、P95约0.001298 mm；最大约1.421 mm。精确BRep顶点与三角化STL的采样差异意味着这些残差不是实机配准公差。完整值在 `validation/final_geometry_audit.json`；不把很小的中位数解读为微米级硬件标定。

## 4. 碰撞体、背壳、轨道不是同一个表面

原 `trunk` 有5个collision box，而非一个覆盖整条背部的精确曲面。主box是：

```text
origin_B = [0,0,7] mm
full_size = [240,280,170] mm
upper_z = 7 + 170/2 = 92 mm
```

其它box位于头尾突出部件并带不同origin/rpy，不能使用所有collision顶点的最高Z来代表安装承托面。5个box的真实参数及旋转后的包围盒均在新审计JSON中。

对原CAD与STL进行垂直射线查询，发现应区分：

* 邻近背壳/轨道下部参考面约89.632 mm；背壳不是处处水平，前部隆起更高。
* 轨道两条承托边条的上表面为92.431555 mm。
* 轨道中央凹槽底面约83.131553 mm，不是承托面。

例如在 `X=24 mm`，Y=102或110 mm击中承托边条，而Y=106 mm击中较低凹槽。不能只取轨道中心一条射线，就把凹槽底错误地当成Vpiper安装高度。

同一承托边条位置，92.431555 mm相对下部参考平面89.631553 mm高约2.800002 mm；因此Owner提到的“背部到导轨有抬升”在该CAD中确实存在。但是主碰撞box的顶部已经是92 mm，接近轨道顶，不是89.632 mm的背壳参考面。所以由collision顶部到轨道真正承托面只剩 **0.431555 mm**，不是再加完整2.8 mm。

**直接回答：visual/STEP有轨道形状；collision没有精确的轨道与凹槽细节。本版既不假装collision是实测安装面，也不在已经包含轨道高度的CAD尺寸链上重复加高。**

## 5. 局部接触面的独立验证

在X={24,48,82,94} mm、Y={−110,−102,+102,+110} mm取16个位置，逐一检查三件事：

1. 原trunk精确BRep的最上交点位于轨道承托面，而且命中的面通过OCCT面级有效性检查。
2. Vpiper精确BRep在同一XY的最下交点确实位于该支脚下表面；不是只比较两个全局包围盒。
3. 原trunk.STL在同一XY通过三角形重心坐标插值得到的表面高度，与前两者一致。

16点CAD接触面高度差在浮点舍入量级，STL最大高度差约0.000052 mm。它们证明所提供几何在这些实际支脚位置闭合；不代表所有网格、所有姿态或实机不存在穿插。

## 6. 完整Z尺寸链及154 mm的解释边界

```text
trunk link原点
 → 轨道承托面                      92.431555 mm
 → Vpiper上承托面              +   50.000000 mm
 → 额外金属板上表面            +    5.000000 mm
 → PiPER原生安装底面到模型原点  +    0.000000 mm
 = PiPER原点Z                     147.431555 mm
```

PiPER原base_link.STL安装底面局部Z≈0，因此无需再加一段“PiPER原生底座厚度”。trunk惯量中的COM origin也不是新的trunk坐标原点，不应另行加到高度链中。

按Owner本轮说明，其起点是collision上表面，则等价链为：

```text
92.000000 + 0.431555 + 50.000000 + 5.000000 = 147.431555 mm
```

旧154 mm扣掉主碰撞箱92 mm和额外板5 mm，剩57 mm；而本CAD中对应的连接件+基准差为50.431555 mm。**这排除了“全部6.568 mm只因collision遗漏导轨”的解释，但不能恢复当时57 mm是怎样量出的。** 上轮99 mm的条件性反推不再用来解释Owner的真实测量流程。

147.431555 mm是在提供的CAD与URDF根系下得到的最终几何值，不是独立实机尺量标定。若将来证实实物轨道、Vpiper或机身版本与CAD不同，应以受控实测的安装基准更新，而不是重新利用collision近似补偿。

## 7. 本版只保留一套默认水平坐标

新默认 `arm_j0` 保持X=145 mm、Y=0和rpy=0，Z采用以上复核值。原来的CAD四孔直接对齐会得到X≈148.212711 mm，是另一装配假设；实物宽板存在长槽，现有照片不能证实其锁紧位置。因此本版不擅自移动X/Y，信息性孔系值仅保留在config，根目录不再放多套竞争装配模型。

安装固定树：

```text
trunk
├── 原四足运动链，保留
├── arm_body0 → 原PiPER运动链，arm_j0只修正Z
└── vpiper_main
    ├── vpiper_support
    └── metal_plate_5mm
```

主件原点相对trunk约 `[143.212711, 0.003547, 92.431555] mm`。主件到支撑件的origin为0，支撑件真实相对位置在mesh中。主件到板下表面为 `[0,0,50] mm`。机械上PiPER坐于板上；描述中保持其arm_j0直属trunk，与安装件构成焊接固定组，避免改变项目直接读取arm_j0.origin的既有语义。

## 8. 验证范围与已知缺失

原20个活动关节的axis、origin、limit、type均保留。原27个link的质量、COM和惯量逐属性保留，原visual/collision几何不改，27个原mesh哈希逐个与Worker包一致。只为原匿名material增加名字以供URDF解析；原颜色不改。

新安装件visual来自重新提取的精确CAD并再次三角化；与旧派生安装件顶点一致性已核对。主件15个、支撑件36个凸碰撞分块保留并重新加载检查，板collision为准确尺寸box。分块填充小孔或凹部，是近似碰撞表示，不是完整接触力学校准。

分别解析URDF和MJCF，对零位及256组随机配置求FK；原四足不变，整条PiPER链仅固定下移6.568445 mm，朝向不变。另对固定根MJCF测试256组配置。随机角只供数学检查，不代表可在实机执行或保证无碰撞。

MuJoCo未安装，本次未取得依赖，因此没有native编译PASS；Isaac同样未导入。MJCF以原关节effort生成直接力矩执行器供检查，原velocity limit另存为不强制执行的元数据；没有原生产控制器、接触求解器和PD参数，所以不能拿该XML直接替代生产plant。

新增三个固定件没有实测质量，URDF不填写虚构inertial，MJCF禁止自动由geom推断。其他导入器不一定遵循MuJoCo扩展，必须检查其实际质量生成设置。实测质量工具默认要求确认没有与源trunk/arm质量重复计算；均匀密度惯量近似也须明确接受。

## 9. 原STEP trunk的拓扑警告

本次更深入的OCCT检查发现，提取的原trunk实体整体不是有效BRep，其中一个侧壁face报告 `BRepCheck_UnorientableShape`。原始与刚体变换后的检查均如此，未进行几何healing。该面在STEP坐标中约为X=[−112.827,−39.569] mm、Y=114.608 mm、Z=[−88.625,−80.825] mm；变换后位于轨道外侧较低的侧壁区域，并非16点所查询的承托顶面。

保留原trunk.STL，不以重建或自动修补的网格替换它。该警告限制了“整个A2实体可以直接进行可靠布尔运算/加工”的说法；不否定已独立验证的承托面和源网格对应关系。新Vpiper主/支撑件与新板均通过各自实体检查。详细状态保存于 `validation/source_trunk_brep_warning.json`。

为什么要 DAgger？

如果只在 teacher 访问过的 state 上做离线 imitation，student 一个小误差就会走到 teacher dataset 没覆盖的 state，误差累积。DAgger 在 rollout 中收集 student 实际会遇到的 state，再请求 teacher label，逐步覆盖这个 distribution shift。

不变的 action boundary

Teacher 与 Student 都学习 12D high-level action。冻结的 A2_Base 继续用 1620D 低层历史产生 12D leg action；两者合成 24D env action。因此视觉蒸馏替换的是高层感知与决策，不是无意中重写整条腿部控制链。

30 秒

Teacher 可以使用训练阶段的较丰富状态，Student 则从 81D proprio、相机输入和 LSTM memory 预测同样的 12D high-level action。DAgger 的要点是让 student 自己 rollout，再由 teacher 给这些偏离后的状态打标签，从而减少 covariate shift。

60 秒

蒸馏的验证至少分三层：先验证 checkpoint 和 input/action contract；再比较 teacher-student action disagreement；最后在统一的环境、reset 与指标下评估 task outcome。项目中的 Phase3 完整 GRPO fine-tuning 路线尚未实现，所以面试中应说已实现的 DAgger/Student pipeline，不把未来方案说成已跑出的阶段。

白板公式与追问

L_distill = E_{s ~ d_student}[ || μ_student(o_student) − a_teacher(s_privileged) ||² ]
DAgger: collect s from learner rollout → query teacher(s) → aggregate dataset
追问：action MSE 小就等于任务成功吗？——不等于。局部 action error 可能在接触、时序和视觉 domain shift 中被放大；它是诊断指标，还需 closed-loop task evaluation。

一个 batched step 发生了什么？

总览系统双环lifecycletensorPPOreward蒸馏sim2sim卡片

不要把 IsaacLab 想成 4096 个 Python for-loop。大多数 state、action、reward、done 都是 device 上的 batch tensor；一个 env.step 同时推进全部环境。

1. 取动作actor high12 + A2_Base leg12 → [N,24]
2. 解码与控制base/arm/gripper/legs 进入 action path
3. physics200 Hz；每控制步 4 个 physics ticks
4. 刷新状态articulation、door、contact、sensor tensors
5. terminationdone[N]：成功、失败或 time limit
6. reward / terminal snapshot用 post-physics state 计算并保存终态事实
7. selective reset只对 done == True 的 env 清理 stage/history
8. next observation组装下一批 actor/critic obs；done 行已是 reset 首帧
30 秒

控制频率是 50 Hz，physics 是 200 Hz，所以每一个 policy action 会被物理积分 4 次。step 后一次性得到 N 个 observation、reward 和 done；不是所有环境一起重来，而是用 done mask 选择性 reset 结束的行。

60 秒

对 lifecycle 最重要的不是函数名，而是时序：action 必须先被写入控制器再推进 physics；termination 与 reward 读取 post-physics state，terminal facts 被保存后才 selective reset，最后组装 next observation。reset 只清理对应 env 的 stage、history 与 action accumulator。顺序错了，训练到的是错位的 MDP。

白板公式与追问

f_physics = 200 Hz, f_control = 50 Hz
decimation = f_physics / f_control = 4
done: Bool[N] → reset(env_ids = where(done))
追问：为什么 actor/critic 的 observation 有 batch 维？——同一网络把 N 个状态作为 N 条独立样本并行推理，网络参数共享；环境之间的隔离靠 batch 维和 reset index 保证。

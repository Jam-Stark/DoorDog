已能说什么

shadow branch 的 MuJoCo 运行、构建与有限性证据能用来说明：机器人/门/控制 contract 被显式化，某些输入输出能复放，且可以观察视觉与动力学 domain gap。r7 的材料支持视觉域差层面的结论。

不能说什么

E5 的正式 Isaac–MuJoCo paired comparison 仍是 BLOCKED_INPUT_ISAAC_PAIRED_TRACE。没有同一 Student、同一 scene、同一 reset 的 Isaac trace，不能把 MuJoCo 轨迹或截图说成 policy parity、任务成功，或 sim2real 证明。

30 秒

我把 sim2sim 看成合同测试：先固定 policy、observation order、action mapping、control/physics timebase 和 door instance，再拿两边同条件轨迹逐行比较。当前 MuJoCo shadow 给出了有价值的实现和视觉域差信息，但 E5 缺 matching Isaac trace，所以正式 paired parity 仍 blocked。

60 秒

跨引擎最危险的是“看起来一样”。画面相似不保证坐标系、关节顺序、力矩限幅、接触、friction 或 reset 一致。我会区分 source contract、single-engine runtime、paired numerical evidence。仅有 r7 视觉材料时，最多说视觉 domain gap；任何 action/trajectory parity 需要匹配 input 和严格 comparator。

row_i = {env_id, episode, policy_step, substep, obs, action12, applied19, target20, q20, qvel20, door, camera, done}

# A2＋PiPER离线动力学与方向出力：实际执行报告

## 执行状态与可复现范围

**EXECUTED_CPU_OFFLINE_MODEL。不是NOT_RUN，也不是只读URDF。** 本次实际执行FK、有界IK、TCP Jacobian、重力、26×26浮动基座刚体质量矩阵、每关节限矩方向力求解、四足支撑/摩擦/腿限矩LP、arm静态PD目标角限位、夹持敏感性、独立base平移、静止瞬时加速度敏感性。原Isaac/策略/实机均NOT_RUN。

环境：Python3.13.5、NumPy2.3.5、SciPy1.17.0；绘图Pandas2.2.3、Matplotlib3.10.8。没有安装/调用MuJoCo、Isaac、CUDA或Pinocchio。使用清晰的最小URDF刚体实现与SciPy bounded least-squares/HiGHS LP，数值与独立关系交叉检查，见下文。此实现不是成熟动力学库的全功能替代，但足以审查所定义静态问题。

读取28个带惯量links、20个配置关节；6维浮动基座速度加20维关节速度，nv=26。URDF总质量 **45.6448083kg**。原始URDF与三份Owner提取输入位于`modeling/inputs/`。模型可脱离原仓库运行，不需加载mesh；原URDF内mesh引用保留，但本程序不使用mesh，因此没有进行碰撞检查。

## 1．输入与动作合同

TCP为`arm_body6_to_gripper`局部`[0,0,0.085]m`，不是该link原点。[S5] arm_j1..6均100Nm、finger45N是C002模拟最大effort；腿hip/thigh120Nm、calf180Nm来自配置CSV。它们**不是已核验硬件峰值/持续能力**。arm Kp为[64,128,64,64,64,64]Nm/rad，finger Kp1300N/m；armature不加入本次刚体M，静态结果不受其影响。

C002高层是base5＋arm6增量＋gripper1；腿由冻结A2_Base生成，不是自由配置关节力矩。静态LP允许分配力矩，是放宽后的机械学可行性，不代表冻结policy能做到。PD额外层纳入了qdot=0、名义增益与arm目标角硬限制，但仍不证明从当前状态经过动作累计/速率/延迟能到达那个目标。

actual config：delta_scale=.3、target_scale=.25、delta_clip=15、hard DOF target clamp=true。参考[S10]额外读取的依赖及包内door覆盖函数。关节角/effort的URDF与C002覆盖差异以`JOINT_LIMITS_AND_ACTUATORS.csv`两列为准；求解使用configured列。

质量/惯量采用名义URDF，不模拟随机质量/电机强度的全域分布，也未证明USD运行时与URDF完全一致。碰撞、自碰撞、门/墙/相机塔净空、关节速度、温升、电机电流、柔性与硬件控制器均未验证。

## 2．坐标、力的对象与方向

世界W：X为中性机器人前方、闭门时门面法向；Y向左，Z向上。所有表中F为**机器人施于门的TCP纯力**：`f_on_door=F*d_W`，F≥0；门施于机器人为`−F*d_W`。TCP处外加力矩设为0；真实刚性抓握可能需要传递力偶，本次未解完整6D抓握wrench。

门左右符号s取source的door_open_lr，右s=−1、左s=+1；正开门角θ对应面板绕W的yaw `−sθ`。F0-like G旋转的三列为`[e, cross(−e,approach), approach]`，`e=[0,−s,0]`、`approach=[1,0,0]`，随后乘`Rz(−sθ)`；这来自B05 G语义。[S4]

方向包括向下压柄−Z、开门切向/门面法向、反向、局部handle轴。对理想平板门，开门切向和门面法向在柄的径向位置重合，**不是独立两个方向的增强证据**。实际handle有面外偏置、弯曲或offset时，应由真实hinge轴与接触点重新算方向和力臂；本次只用F0-like姿态，不声称覆盖全部七族的真实接触约束。

每个姿态对照固定世界TCP完整位置和旋转、base xyz和四个foot球心，重新解腿与arm关节角。不是只旋转arm局部坐标，也不是只算manipulability椭球。左右方向变换显式处理，不能把右门roll＋8°推荐无条件复制到左门。

## 4．最小刚体模型与方向力问题

每个link的URDF惯量先从惯性坐标旋转到link，再到世界；对COM计算线/角Jacobian。令ν=[v_base,W,ω_base,W,qdot]，

`M(q)=Σ_i [m_i Jv_iᵀJv_i + Jw_iᵀ R_i I_i R_iᵀJw_i]`，

`g(q)=Σ_i Jv_iᵀ [0,0,m_i*9.81]`。

这里g是需执行器/接触抵消的重力项，真实重力外力为−mg e_z。浮动基座动力学的描述为

`M(q)νdot + h_velocity(q,ν) + g(q) = Sᵀτ + Jfeetᵀf_ground − Jtcpᵀ(F d)`。

实际程序计算M与g；在ν=0时velocity项为0。**没有实现任意非零速度Coriolis/离心全模型，也没有进行时间积分的整机开门模拟。**

### 层A：arm限矩方向边界

固定姿态下，`τ_arm(F)=g_arm + Jtcp,armᵀ d * F`。对六关节逐项解
`τ_lo ≤ τ_arm(F) ≤ τ_hi, F≥0`，得一维区间交集的最大F；和独立LP核对。重力可以沿某方向协助、另一方向抵消；`arm_no_gravity_force_N`仅作敏感性，不作主结论。

若某方向Jacobian投影为0，不通过人为最大N裁剪掩盖无界；若重力/区间不满足则标INFEASIBLE。本次选定方向未出现UNBOUNDED，不意味着其他奇异姿态也有有限机械刚度。本模型未计link/轴承结构强度。

### 层B：足地、腿和基座平衡

LP未知为F与四足各3D接触力。约束浮动基座6维平衡、20个关节effort、足法向非负，以及
`|fx|+|fy| ≤ μ fz`，主μ=.6。

这是圆锥的**内接摩擦棱锥**：对真实圆形Coulomb锥偏保守；对省略的抓握/碰撞/冻结低层控制又偏乐观。因此本报告称“给定抽象下的支撑边界”，不把它当真实机器人严格上界或下界。接触点无附加力矩，无动态换脚。

最大值通常处于一个或多个足的法向力降为0的边界，并非稳定带裕量的工作推荐。`solver_details.json`保存接触力、关节力矩、等式残差、最小不等式slack及约束dual；不是仅凭图形猜测支撑限制。

### 层C：arm静态PD目标限位

C002累计arm目标会被硬关节位置限位裁剪。静止、名义增益下，除了effort限制，还需

`max(−τcap,Kp*(qmin−q)) ≤ τ_arm ≤ min(τcap,Kp*(qmax−q))`。

将这组不对称τ边界代入层A/层B。仅对arm使用此目标夹取规则，腿仍为抽象可分配力矩，未假称冻结腿policy等价于LP。delta clip±15经.25缩放给default±3.75rad，当前configured arm limits更紧。所有104例的20N静态需求所需目标都落在这些arm限位内；但极限出力处的排序可以改变。

### 层D：假设夹持限制

给定两相反法向±n、每指0≤N_i≤Nmax、摩擦μg，忽略接触力矩和实际几何，沿d的纯力必要界为

`F_grip ≤ 2 μg Nmax / ( ||d−(d·n)n|| + μg |d·n| )`。

这是理想两指摩擦/法向平衡的参数界，不能确认真实接触点、B05局部法向、扭矩承载或形状锁合。真实弯杆/offset/锥度需完整contact wrench；没有将此公式作为七族抓握验证。碰撞/摩擦组合/接触刚度及实际夹持N均未确认。

## 6．夹持、支撑参数与base平移

每指45N仅是模拟effort上限。对水平开门方向，理想两指μg=.2/.4/.8分别给18/36/72N，上述posture arm边界变化可能完全不影响这个瓶颈。当前假设指位q7=.014、q8=−.014m，闭合目标0、静态Kp1300，得到名义18.2N/指；相应μg=.4的水平界14.56N。**假设指位不是已测量的夹持宽度，18.2N也不是实际接触力测量。**

向下方向恰与该F0-like工具闭合轴相关，可由两指法向不平衡承受，因此不能把水平公式2μN无条件用于压柄。实际需要的力偶/偏心和受力表面可能使真实能力更小；也可能有包络形状承载，本次未解。

`sensitivity.csv`还包含ground μ=.3/1.0、arm模拟限矩缩为.1/.2的敏感性；它们不是硬件参数假说或置信区间。每项只改一个假设，不把结果混入主表。

**独立base移动实验**：保持中位TCP完整位姿和脚位，base neutral前后各平移5cm、重新解IK。后移时支撑边界100.763N、中性119.694N、前移138.865N（前移约+16.02%）。这比本例pitch＋8°的+1.22%更大。base移动并不属于纯roll/pitch增强；也没有检查靠门侧净空，不能建议直接向门前移5cm。结果支持把base位置纳入候选而非要求arm-led必须base静止。

## 7．瞬时惯性敏感性：已执行但不是甩门仿真

在每个解出的姿态ν=0时，解arm的6×6任务Jacobian，使TCP沿开向加速度±.5m/s²、角加速度0；base/腿瞬时加速度0。用`g_eff=g+M[:,arm]qdd_arm`重新求限矩与支撑边界。中位中性时峰值qdd≈1.598rad/s²，惯性增加的arm峰值τ约.415Nm；+.5m/s²时支撑边界119.694→118.362N，−.5时121.026N。

这说明非零加速度会消耗/改变余量；它没有积分门与整机、未考虑未来速度/足地冲击、未建立门惯量与机器人加速度的闭环耦合，也未加入此动态情形的PD target envelope。因此不能从静态或此单时刻敏感性证明快速swing、动量利用或撞门安全。

## 8．数值核对与未解项

每个解出的姿态做TCP关节Jacobian中心差分、独立势能差分验证g、质量矩阵对称/正定检查、arm解析区间与独立LP比较。全体最大Jacobian差约2.74e−10；g误差约4.30e−8Nm；解析F与LP差0；质量矩阵最小特征值约2.96e−4；LP平衡最大残差约5.52e−12。

额外中位检查浮动Jacobian与g的差分，并直接对各足、重力与TCP反力做Newton/Euler平衡：力残差约5.68e−14N、力矩约3.13e−14Nm。它们支持当前实现的数值/符号一致性，不证明URDF惯量或真实接触模型正确。

没有unbounded结果时仍保留程序处理；IK失败保留而非任意削力、截断N数或更换TCP凑正结果。各状态的q、目标、残差、J奇异值在`states.json`；单个26×26 M/g/J在NPZ；约束解在JSON，可复核。

## 9．对N02目标的反向修正

本次结果使“估计大负载→roll/pitch增加力”降级为未经证实的粗糙启发式。更值得估计的是：当前交互是否有效；这个受真实动作链限制的方案能否产生进展；持握或释放能否留足通过时间。当前q/重力与目标限制可确定性计算，实际跟踪误差可直接观测，不需要先把它们转成全身wrench神经网络。

优先序应为：排查接触/解锁 → 确认命令兑现 → 中性arm与base重配置 → 仅在相关方向/工作点确有收益时倾斜 → 依据释放后果选择hold/swing。若瓶颈是grasp，增大arm力上界不会解决；若瓶颈是PD目标角/IK，姿态应针对几何配置；若瓶颈是支撑，必须连base位置/脚接触考虑，而不能只看arm Jacobian。

**证据终点**：模型方向增强存在；C002 Isaac控制跟踪、已学policy的主动选择、Student迁移、七族真实抓握和硬件持续出力均尚未得到本次实验支持。

  3. 两个从未被任何一轮实验触碰过的差异

  (a) a2_stage2_squeeze_force_min：v19 = 2.0，v26 = 0.5

  源码 gr00t/rl/envs/door/door_open_a2_base.py:17701：

  sufficient_squeeze = torch.all(squeeze_abs > squeeze_min, dim=-1)

  K5 gate 谓词直接吃这个下界。v19 要求两指侧向力都 >2.0 N 才算「抓住」，v26 只要
  >0.5 N —— 门槛低了 4 倍。

  Wave A 的读数正好和它同形：restored/right 的 Stage3 admission 是
  63/64（几乎人人过关），但只有 44/64 能持久按住 handle，门一点不动。也就是说
  v26 的策略学到的是「用刚够过 gate 的最小力捏住」—— 那是它在 10 N 上限下优化
  7,000 batches 的最优解，而 0.5 N 的 gate 一直允许它这么做。Wave A §3 明确写了
  「刻意不改，因为会变成第二个自变量」，这个决定在当时是对的，但它留下的正是
  v19/v26 之间唯一没测过的 gate 语义差异。

  5. 「压下去」和「推开门」是两关，别混成一关

  Wave A：44/64 把 handle 按在 >0.6 rad 长达 p50 64、max 187 control step，hinge
  最大 0.0111，而 door_body_panel_normal_force_total 在整个保持期为 0 ——
  机器人根本没往门上施加任何力。v26-3 的 U-probe 又证明门在 handle 0.6 rad 时
  hinge 可自由到 0.1443 rad。

  Stage3 收入构成（push_door_hinge 实现在
  door_open_a2_base.py:16737，hinge_vel*10 + hinge_pos/1.5708 后 clamp 到 1）在
  hinge≈0 时几乎不付钱，而最大的 target_root_distance（scale 12）只在
  STAGE_SWING/THROUGH 生效。所以 Stage3 里「按住不动」是严格占优，直到 hinge
  大到够拿 Stage4 的钱。

  Wave B 只处理第一关。即使它成功，第二关仍在。

  - reward 完全 side-invariant — 从来没告诉 policy 这两侧需要不同的解；
  - observation 有 side one-hot — policy 知道自己在哪一侧；

  一个网络被要求用共享参数表示两套本质不同的运动学解，只靠 one-hot
  切换。它能做的最省力的事就是学一个两侧都"不太差"的折中。Wave A

  typed route，是为了 side 分解。
  2. 如果 RIGHT 单独看有明显提升而 LEFT 仍是 
  0，那就是共享参数被拖累的直接证据。正确处理是分头训练（RIGHT-only / LEFT-only

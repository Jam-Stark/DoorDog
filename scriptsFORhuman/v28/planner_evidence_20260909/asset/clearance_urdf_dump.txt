## 3. 直接挂到运动机器人，不要求先通过硬件验收

在Isaac Sim/Isaac Lab应用已经初始化、机器人已经生成后、Camera传感器构造和sim.reset之前调用：

```python
from pathlib import Path
import sys
import omni.usd

BUNDLE = Path('/path/to/U3_forward_delivery')
sys.path.insert(0, str(BUNDLE / 'code'))
from attach_isaac import install, make_existing_camera_cfgs

receipt = install(
    omni.usd.get_context().get_stage(),
    BUNDLE / 'config/U3_F0.json',
    robot_root='/World/envs/env_0/Robot',  # 改为你的实际机器人根路径
    supports=True,
    housings=True,
    replace=True,
)
# 如使用Isaac Lab，则据这些config构造Camera并加入既有sensor生命周期：
configs = make_existing_camera_cfgs(receipt, include_right_ir=True)
```

`replace=True`明确替换旧`DoorDogCameraRig`，不要同时叠加旧U1/U2/U3视角。脚本将base挂到trunk、wrist挂到法兰link上，而不是固定到世界坐标。新增的overlay没有RigidBody、Collision、Mass等physics API，不改变policy。

固定关节合并时，只有输入URDF中与F重合的`arm_body6`被允许作自动等价parent。其他名称映射、缩放、实例代理会显式报错，不会悄悄把腕相机挂到trunk。多个env应在克隆前安装或逐env使用实际prim路径。

用`U3_F15.json`替换路径可做同一记录/同一场景的固定角度对照，不需要修改动作。手动隐藏支架的诊断选项不能被解释成实物支架已经不存在或已无冲突。

## 4. 最小渲染检查

```bash
./isaaclab.sh -p /path/to/U3_forward_delivery/code/smoke_isaaclab.py \
  --plan U3_F0 --bench-targets --enable_cameras --headless \
  --save-dir /tmp/u3_forward_F0_smoke
```

同理改为`--plan U3_F15`做对照；`--no-supports`可用于分离支架遮挡，`--stream-mode six`只启动每台RGB+depth，默认`nine`另外启动右IR视点Z-buffer诊断。

该脚本使用完整静态机器人参考几何，输出每路RGB PNG／数组、理想光轴深度数组、实际K及变换核对；**不是原始阶段任务回放**。合成格板只是检查前视相机朝向/渲染输出，不把它作为真实随机门场景证据。本环境未运行这个Isaac脚本，运行记录由你的本地环境产生。

纯viewport可直接打开`*_reference_scene.usda`或`*_forward_bench.usda`。这些场景是静态视觉场景；运动机器人要使用上面的挂载接口或模型导入路径。

`robot/a2_piper_*_camera_visuals.urdf`保留原关节／惯性／碰撞字段，增加visual和fixed optical frames；无惯性的新增fixed link如何被具体URDF importer合并/补默认质量，尚未运行验证。因此要严格保持现有仿真物理不变，优先使用USD overlay接口，而不要假设所有导入器都会完全忽略新增fixed link。

`*_clearance_only.urdf`则显式增加外壳／支架碰撞包络，仅供单独的机械扫掠检查，不能冒充不改变物理的默认视觉版本。

## 5. 前视职责与接触职责的真实边界

原U3朝向按对准近端TCP选取，参考姿态下俯约63.867°。本版改为前视，是按Owner要求改变优先级，不再用“让TCP居中”决定镜头方向。

但180mm塔架与F+Z85mm近端TCP存在几何冲突：在当前名义光学模型下，U3_F0和U3_F15均不能把这个近端点放入RGB。参考姿态下，一个与TCP同B高度、位于法兰正前方的点，分别约要到**0.458m／0.243m**才进入三流共同视野；这个距离来自几何扫描，不是实际handle已验证的工作距。

因此不能宣称“主方案默认前视，同时S3完整握持区也已解决”。这次已经交付可直接放sim的前视方案；S3/4外露handle／手指与base互补是否够用，需要你用实际阶段画面继续验证。固定在法兰上的TCP和相机的相对位置不随整条arm/base转动而改变，不能把“arm动起来”当作会自动把刚性近端TCP移回图像的理由。

S5也只有在arm实际恢复接近参考方向后，腕机才恢复前视。`docs/PHASE_ROLE_CONTRACT.md`逐阶段列出了设计职责、已知冲突和待验证项；`code/phase_diagnostics.py`可从既有环境读取实际变换/目标，输出各流像素和相对base前向方向，不改任何动作、stage或相机位姿。

## 6. 本轮完成的计算

- 冻结U3塔架位置与两台base配置，重算新俯仰、九路光学／USD变换及支架。
- 对指定参考姿态和0/20/35mm三种手指关节半开度做前向合成点、TCP、实际两指表面样点及160×90网格射线检查。
- 检查相机／支架包络与已知机器人网格在上述静态姿态中的表面相交；不将零命中解释为连续扫掠、门板或实机安全通过。
- 从原机器人三角网格计算四视图SVG，原mesh不做显示简化；另用独立逐三角形算法复核样例射线首交。
- 核对新URDF中原关节、惯性、原碰撞字段未变，optical frame FK与JSON一致，ROS optical(+Z前,+Y下)和USD(-Z前,+Y上)轴转换一致。
- 检查所有SVG为纯矢量、XML正确、ID唯一；附CSV、JSON、NPZ和完整代码。

原完整stage轨迹不在本轮上传的模型／图包内。本轮**没有重新处理1536集、没有S0/1/2/3/4/5新覆盖率，也没有实拍或真实有效depth结果**。这里的静态射线栅格不是RGB图像像素的真实测量。
